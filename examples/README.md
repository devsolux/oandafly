# Metadata templates and schemas

These are source examples, **not deployment inputs or signed approvals**. Files ending
in `.template` deliberately contain placeholders. Replace every placeholder using
actual observations, measured costs and independent review; do not use invented hashes,
sign fixture results as full-model qualification, or weaken a validator to accept a template.

| File | Purpose |
|---|---|
| `worker.shadow.json.template` | No-write practice-feed composition; no execution credential, grant or deployment |
| `worker.practice.json.template` | Separately authorized native practice account |
| `worker.live.json.template` | Separate live account, credential scope and live deployment evidence |
| `account-profile.json.template` | Actual broker entity, product, eligibility and instrument rules |
| `credential-reference.json.template` | Secret metadata only; never the broker token |
| `trust-policy.json.template` | Public signer roles, validity and revocation; each role needs a distinct key |
| `eligibility-evidence.json.template` | Unsigned evidence claim for actual account review |
| `authorization-grant.json.template`, `risk-limits.json.template` | Operator-approved exact bounds; no suggested trading allocation is supplied |
| `dataset-review.json.template` | Unsigned complete-topology and source/signs review claim |
| `model-validation.json.template` | Unsigned measured evaluation/scenario claim |
| `deployment-approval.json.template` | Unsigned model/account/environment deployment claim |
| `candidate-reference.json.template` | Approved registry metadata; not a raw training output queue |
| `training-spec.json.template` | Existing trainer defaults for inspection, not an optimized strategy |
| `cost-assumptions.json.template` | Measured/reviewed cost fields; no fabricated zero-cost evidence |

For schemas, see `schemas/`. Runtime graph/model manifests are generated by graph import
and training; they must not be fabricated from a hand-written template. Signing a claim
is a separate CLI operation after substantive review. Structural schema validation does
not establish truth, account eligibility, strategy quality or authority to trade.

Copy selected templates **outside the checkout** into an owner-only directory. Use
0600 for metadata documents and 0700 for their private directories. Resolve UUIDs,
UTC intervals, instrument rules, file paths and the actual service-account home.
No `.env` token file is used. See [bootstrap](../docs/BOOTSTRAP.md),
[external artifacts](../docs/ARTIFACTS.md) and [systemd deployment](../deploy/systemd/README.md).
